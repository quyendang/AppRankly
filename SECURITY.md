# Security

Personal, single-owner deployment. Use HTTPS and restrict Railway project/Variables/volume access. Secrets are server environment variables only; no credential editing endpoint exists.

Controls: fail-closed authentication, bcrypt password hash, 12-hour HttpOnly/Secure production/SameSite Strict cookies, Origin checks, request limits, CSP, allowlisted settings and outbound notification hosts, controlled AI payload previews, no generated SQL execution, and symlink/path checks for Markdown notes. Application logging and responses redact configured secrets. No redactor can recognize arbitrary unknown credentials pasted into free text: do not store secrets in notes, listings or notification messages.

Google/Apple SDKs contact their services; public ASO search contacts app stores; AI contacts the official provider or operator-configured OpenAI/Anthropic HTTPS proxy after explicit user action (preview confirmation for analyses, or clicking AI-Generated Response for a review draft); optional notifications contact their configured supported destination after enabling. Railway and administrators can access runtime environment/data. Restrict permissions and rotate compromised keys at their issuer.

Run `npm test --prefix app` and dependency audits before deployment. Mock tests do not prove real provider permissions, Docker volume behavior, Railway deployment success or all possible leaks. Report suspected vulnerabilities privately to the repository owner; do not attach real keys to issues.

Custom AI endpoints are server environment variables only. URLs reject embedded credentials, query strings, fragments and non-HTTPS schemes by default. The explicit `AI_ALLOW_RAILWAY_INTERNAL_HTTP=true` option permits HTTP only to a single-label service hostname under `.railway.internal`, for Railway private networking; it does not permit public HTTP, IP literals, localhost or redirects. OpenAI/Anthropic requests reject redirects and disable automatic retries/fallback. A proxy receives the AI key selected for that provider and the approved prompt; configure a proxy-issued key and review its data handling. The preview exposes the destination origin/model for review, not the full configured URL. Store credentials must never be included in that payload.

Review-draft generation automatically creates and consumes a server-controlled one-use payload for the selected review. The generation click authorizes that AI request; it never authorizes publishing. The payload excludes private notes, analytics and store credentials. All generated replies remain editable and require a separate public-post confirmation.
